AI + Data Governance Content Engine (Zapier)

0 to 1 Build Guide: Mining Topics, Generating Content, Scheduling, Approvals, Publishing (LinkedIn + WordPress + Substack Assist)

Zapier Tables WordPress REST API LinkedIn Publishing Substack Assist

What you are building

A mostly automatic content operations system that pulls AI and data governance news, mines it into topic ideas, generates drafts for multiple channels, routes drafts through approvals, publishes automatically where possible, and tracks status to avoid duplication.

  • LinkedIn: automated publishing via Zapier.
  • WordPress: automated draft creation + scheduled publish.
  • Substack: draft assist + reminders + RSS verification.

3. Tools you will use

  • Zapier Tables (database + triggers)
  • Zapier Forms (approvals without database access)
  • Schedule by Zapier (time-based dispatchers)
  • RSS by Zapier (news ingestion, Substack verification)
  • Webhooks by Zapier (WordPress REST API)
  • Code by Zapier (hashing, parsing, filtering)
  • LinkedIn by Zapier (publish posts)
  • ChatGPT / OpenAI steps (scoring, mining, generation)
  • Google Docs (optional draft editing)

4. Standard word counts

These constraints keep output consistent and predictable on the calendar.

5. Security rules (read this before you build)

  • Do not store passwords or API keys inside Zapier Tables, Google Docs, or Word docs.
  • Use a dedicated WordPress automation user (role: Editor) and an Application Password.
  • If credentials leak, revoke and recreate immediately.
  • Keep Settings.publishing_enabled OFF until tests pass end-to-end.

6.1 Accounts you need

  • Zapier account (paid plan or trial for multi-step Zaps).
  • LinkedIn account with publishing access.
  • WordPress admin access to thesisstrategy.com (self hosted).

7. WordPress setup for thesisstrategy.com (one-time)

  1. Confirm the REST API is reachable. Open https://thesisstrategy.com/wp-json/ and confirm JSON returns.
  2. Create a dedicated automation user. Users → Add New → username zapier_publisher (role: Editor).
  3. Create an Application Password. Name it “Zapier Publishing”, store it in a password manager.
  4. Test authentication. 
    curl --user "zapier_publisher:YOUR_APP_PASSWORD" "https://thesisstrategy.com/wp-json/wp/v2/users/me?context=edit"

If it fails, check:

  • Security plugins or WAF rules blocking wp-json or Basic Auth.
  • Site reachability from Zapier.
  • Permalink configuration issues.

11. Build the automation Zaps (Phase 4)

Build these in order. Keep Settings.publishing_enabled OFF until Phase 7.

11.1 ZAP A: RSS → News_Inbox (dedup + AI score)

Purpose: ingest headlines without duplicates and score governance relevance.

  1. Tables: Find Record in News_Inbox where news_url = RSS item link.
  2. Filter: Continue only if no record is found.
  3. AI step: produce JSON with summary, tags, relevance_score.
  4. Code by Zapier: parse JSON safely (optional).
  5. Tables: Create Record in News_Inbox, set used_for_topic = unchecked.

AI prompt template

Return ONLY valid JSON with keys: summary, tags, relevance_score.
summary: max 2 sentences.
tags: 3-6 short tags.
relevance_score: integer 1-5 (5 = urgent enterprise governance impact).

Title: {{title}}
Snippet: {{content}}
URL: {{link}}

Optional JSON parse helper (Code by Zapier)

let parsed = {};
try { parsed = JSON.parse(inputData.raw || "{}"); } catch (e) { parsed = {}; }
return {
  summary: parsed.summary || "",
  tags: Array.isArray(parsed.tags) ? parsed.tags.join(", ") : (parsed.tags || ""),
  score: Number(parsed.relevance_score || 3)
};

11.2 ZAP B: High-signal News → Create Topic

Purpose: automatically turn important news items into Proposed topics.

  1. Trigger: New Record in News_Inbox.
  2. Filter: relevance_score ≥ 4 AND used_for_topic unchecked.
  3. AI step: generate one topic object.
  4. Tables: Find record in Topics where dedup_key matches.
  5. Filter: continue only if NOT found.
  6. Tables: Create Topic with topic_status = Proposed.
  7. Tables: Update News_Inbox used_for_topic = checked.

11.3 ZAP C: Weekly Topic Suggestions (batch clustering, optional)

Trigger weekly, find top news, ask AI to propose 5 topics, and loop to create Topic records (Proposed).

11.4 ZAP D: Topic Approved → Generate Draft Assets

Purpose: generate LinkedIn, Substack, and WordPress drafts plus reserve slots.

  1. Trigger: Updated Topics record where topic_status changes to Approved.
  2. AI step: generate three drafts as strict JSON.
  3. Code step: compute word counts + sha256 hashes.
  4. Reserve earliest Available Calendar_Slots per channel.
  5. Create 3 Content_Assets records with Draft status.
  6. Optional: create Google Docs for each draft.

11.5 ZAP E: Asset → Request Review (button)

Move an asset from Draft to In Review and notify reviewers.

11.6 ZAP F: Approval submission → Update Asset

On Approval_Log record, update asset status and store comments.

11.7 ZAP G: Dispatcher → Publish LinkedIn (auto)

Schedule every 15 minutes, gate by Settings.publishing_enabled, post due LinkedIn slots.

Code step to find due slots

// Input line items: scheduled_datetime[], slot_id[], asset_id[], slot_status[]
const now = new Date();
const times = inputData.scheduled_datetime || [];
const slotIds = inputData.slot_id || [];
const assetIds = inputData.asset_id || [];
const statuses = inputData.slot_status || [];

let due = [];
for (let i = 0; i < times.length; i++) {
  if (!times[i]) continue;
  if (statuses[i] !== "Reserved") continue;
  const t = new Date(times[i]);
  if (t <= now && assetIds[i]) {
    due.push({ slot_id: slotIds[i], asset_id: assetIds[i], scheduled_datetime: times[i] });
  }
}
return { due };

12. Images (optional add-on)

12.1 Simple approach (recommended first)

  • Pick a featured image in WordPress before publishing.
  • Publish LinkedIn as a link-share to the WordPress URL.
  • Insert the same image manually in Substack.

12.2 Fully automated featured images (advanced)

  • Generate or download an image.
  • Upload via REST API: POST /wp/v2/media.
  • Set featured_media on the post.

13. Avoid duplication (required guardrails)

  • Topic dedup_key is unique. If duplicate, archive the topic.
  • Content hash (sha256) blocks duplicate bodies before approval.
  • Optional: check WordPress slug before creating posts.

14. Go-live checklist (Phase 5)

  • Confirm Settings.publishing_enabled is OFF.
  • Run ZAP A with one RSS feed and confirm News_Inbox fills.
  • Confirm ZAP B creates at least one Proposed topic from high-signal news.
  • Approve a topic and confirm ZAP D creates 3 Content_Assets + reserves slots.
  • Run review end-to-end: submit_for_review → approval form → status Approved.
  • Approve a WordPress asset and confirm a DRAFT appears.
  • Schedule LinkedIn slot 10 minutes out, turn publishing_enabled ON, confirm publish.
  • Schedule WordPress slot 10 minutes out, confirm publish + URL write-back.
  • Publish Substack manually, confirm RSS verification marks Published.

15. Operating rhythm (Phase 6)

15.1 Daily (10–15 minutes)

  • Scan News_Inbox and fix obviously wrong scores/tags.
  • Star high-signal items for topics.

15.2 Weekly (45 minutes)

  • Approve next week’s topics.
  • Review drafts and request changes.
  • Ensure one week of slots is reserved.

15.3 After publishing (10 minutes)

  • Capture basic metrics (views, comments, saves, click-through).
  • Turn audience questions into follow-up topics.

16. Troubleshooting (common failure modes)

16.1 WordPress draft creation fails (401/403)

  • Re-run the curl test in section 7.4.
  • Check WAF/security plugin rules blocking wp-json or Basic Auth.
  • Confirm Application Passwords are used.

16.2 LinkedIn publishes but no URL returned

Mark the asset Published anyway and paste the URL manually if needed.

16.3 RSS feed ingestion fails

  • Some sites block bots. Try a different feed.
  • Use regulator/standards feeds for reliability.
